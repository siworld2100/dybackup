# 升级发布服务（本地电脑版）

这套东西只有一个目的：**抖音改接口、你修好之后，能让用户拿到新版**。

整套服务没有数据库、没有账号、没有后端框架，就是「一个目录 + 一个 HTTP 服务」：

```
publish/
  latest.json                 <- 版本清单（带签名）
  dybackup-v1.2.1-arm64.apk   <- 安装包
```

App 启动时拉一次 `latest.json`，验签、比版本号，有新版就提示下载。

---

## 一、先确认你的公网 IP 是真的公网

这一步最容易被跳过，但它是后面所有步骤的前提。

| 检查项             | 怎么做                      | 结论                         |
| --------------- | ------------------------ | -------------------------- |
| 路由器 WAN 地址      | 登录路由器后台，看「外网地址 / WAN IP」 | 记下来                        |
| 真实出口 IP         | 手机流量或电脑打开 ipip.net       | 记下来                        |
| 两者是否一致          | 对比                       | 不一致 = 运营商 NAT，端口映射无效       |
| 是否落在 100.64.x.x | 看 WAN IP                 | 是的话属于运营商级 NAT，必须找客服申请公网 IP |

只有两个地址一致，端口映射才有意义。这一步不通，后面的都不用试。

---

## 二、发布一个新版本

改完代码、打好包之后，在工程根目录执行（Windows 命令提示符）：

```bat
flutter build apk --release

python tools\server\make_manifest.py ^
  --apk build\app\outputs\flutter-apk\app-release.apk ^
  --base-url http://你的公网IP:8080 ^
  --notes "修复抖音新版分享页解析失败"
```

脚本会算出 sha256、读出 APK 的 versionCode，生成 `publish/latest.json`，并把 APK 复制进 `publish/`。

注意 `--base-url` 要写**用户手机能访问到的地址**，不是 127.0.0.1。

---

## 三、启动服务

```bat
python tools\server\serve.py --port 8080
```

启动后会打印三个地址（127.0.0.1 / 局域网 / 公网），照最后一行去测。

**不要用 80 或 443**：大陆运营商普遍封锁家宽的入站 80/443，用这两个端口大概率连不上。8080、8443 这类都没问题。

---

## 四、让手机连得上

分三种情况，逐个排除。

### 情况 A：手机和电脑在同一个 WiFi

通常直接能通。如果不行，多半是 Windows 防火墙拦了：

1. 控制面板 → Windows Defender 防火墙 → 高级设置 → 入站规则 → 新建规则
2. 选「端口」→ TCP → 特定本地端口填 `8080` → 允许连接 → 全部勾选 → 命名 `dybackup-publish`

### 情况 B：手机用 4G/5G

需要在路由器上做端口映射（不同品牌叫法不同：虚拟服务器 / 端口转发 / NAT）：

| 项     | 填什么                          |
| ----- | ---------------------------- |
| 外部端口  | 8080                         |
| 内部 IP | 电脑的局域网 IP（`serve.py` 启动时会打印） |
| 内部端口  | 8080                         |
| 协议    | TCP                          |

电脑的局域网 IP 建议在路由器里绑定成静态，否则重启后变了映射就失效。

### 情况 C：公网访问仍不通

按这个顺序查：

1. `serve.py` 那台电脑是不是在跑（看有没有日志输出）
2. 防火墙规则是否对「专用网络」也生效（很多人只勾了公用）
3. 端口映射的内部 IP 是不是当前电脑的 IP
4. 光猫是不是也在做 NAT（桥接没做好时要双重映射）
5. 回到第一节，确认公网 IP 是真的

---

## 五、验证清单

按顺序做，每一步都能定位问题在哪一层：

| 步骤 | 操作                                 | 通过标准                         |
| -- | ---------------------------------- | ---------------------------- |
| 1  | 电脑浏览器开 `http://127.0.0.1:8080/`    | 看到文件列表                       |
| 2  | 同 WiFi 手机浏览器开 `http://局域网IP:8080/` | 看到文件列表                       |
| 3  | 手机切 4G 开 `http://公网IP:8080/`       | 看到文件列表                       |
| 4  | 打开 `.../latest.json`               | 返回带 `payload` 和 `sig` 的 JSON |
| 5  | 打开 APK 链接                          | 开始下载，能看到总大小                  |
| 6  | App 内点「使用说明 → 检查更新」                | 提示发现新版本                      |

第 2 步不通是防火墙问题；第 3 步不通是端口映射问题；第 6 步不通但前几步都通，是 App 里的地址没改对。

## 六、改 App 里的服务地址

**推荐：在 App 内改，不用重新打包。**

打开 App → 右上角「使用说明」→ 滑到底 → **连点「当前版本」这一行 5 次** → 弹出地址输入框。  
填 `http://你的IP:8080/latest.json` 保存即可，立即生效。地址存在本地偏好设置里，  
点「恢复默认」会回到编译期写死的那个。

这个隐藏入口是给验证阶段用的：换 WiFi、公网 IP 变了，改一下就能继续测，  
不必每次都重新出包。

地址与密钥都**不在代码里**，统一放在本目录的 `secret.env`（已 gitignore）：

```ini
MANIFEST_KEY=你的随机密钥
MANIFEST_URL=http://你的地址:8080/latest.json
```

| 谁在读它 | 用途 |
| --- | --- |
| 工程根目录的 `build_apk.bat` | 拼成 `--dart-define` 打进 App |
| `make_manifest.py` | 取 `MANIFEST_KEY` 给清单签名 |

第一次用先 `copy secret.env.example secret.env` 再填值。两边读同一个文件，
所以**不存在「改了 App 忘了改服务端」这类签名对不上的问题**。

> `secret.env` 必须是纯 ASCII、CRLF 换行。cmd.exe 用系统 ANSI 码页解析它，
> 里面写中文会让 `for /f` 吞掉下一行——这个坑已经踩过一次了。

手动构建时也可以直接传参（不依赖 secret.env）：

```bat
flutter build apk --release ^
  --dart-define=MANIFEST_URL=http://1.2.3.4:8080/latest.json ^
  --dart-define=MANIFEST_KEY=你的密钥
```

两个值缺任一个，App 会安静地跳过在线更新（解析、下载不受影响）。

## 七、开机自启（可选）

验证阶段手动启动就够了。确认要长期跑，再考虑：

1. 任务计划程序 → 创建任务 → 触发器「登录时」
2. 操作：启动程序 `python`，参数 `tools\server\serve.py --port 8080`，起始于工程根目录
3. 勾选「不管用户是否登录都要运行」需要管理员权限

更省事的替代方案是把 `publish/` 整个目录丢到对象存储（腾讯 COS / 阿里 OSS），  
月成本几元，可用性远高于一台会关机、会重启、会断电的家用电脑。

---

## 八、这套方案的已知边界

| 项       | 现状                                                              |
| ------- | --------------------------------------------------------------- |
| IP 会变   | 家宽多为动态 IP，重启光猫后公网地址可能变化，需要在路由器配 DDNS，或手动更新 `--base-url` 后重新发布清单 |
| 电脑关机    | 服务即不可用。App 侧的静默检查会安静失败，不会打扰用户                                   |
| 明文 HTTP | 清单有 HMAC 签名、安装包有 sha256 校验，篡改不了；但传输内容可被旁观者看到（内容不敏感）             |
| 密钥是对称的  | 理论上可从安装包逆向后伪造清单。挡的是低成本劫持，不是职业攻击者。正式发布前应换成非对称验签                  |
| 单点      | 只有一台电脑在服务，没有冗余。验证阶段可以接受                                         |

---

## 九、什么时候该换方案

出现下面任一情况，就该把 `publish/` 搬到对象存储：

1. 用户超过几百人，家里上行带宽成为瓶颈
2. 你开始需要「7×24 小时一定能连上」
3. 一次断电导致用户更新失败并来投诉

搬家时只需要改 `--base-url` 和 App 里的 `manifestUrl`，脚本与服务逻辑都不用动。
